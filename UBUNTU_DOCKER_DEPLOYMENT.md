# ARMSS Photo Studio — Ubuntu Docker Deployment Guide

> Mirrors the same pattern used for **ARMSS-OTT**. Uses **Docker Compose v2** with a fully isolated private network — zero port conflicts with any other running containers.

---

## 1. Architecture Diagram

```
[ User Browser / Mobile ]
           │
           ▼  (HTTP or HTTPS via your domain)
[ Ubuntu Server — Docker ]

  Port 8070 ──► armss_studio_nginx (Gateway)
                       │
         ┌─────────────┼──────────────────────┐
         ▼             ▼                      ▼
      Path: /       Path: /api/         Path: /files/
      Frontend      Backend API         Static storage
      (nginx:80)    (backend:8080)      (backend:8080)
                         │
              ┌──────────┴────────────┐
              ▼                       ▼
          MySQL (3306)           MinIO S3 (9000)
       armss_poster_studio    armss-poster-studio
                                (bucket)

  * All internal ports (3306, 9000, 8080, 80) stay inside
    'armss_studio_network' — ZERO host port conflicts.
  * Only port 8070 (configurable) is exposed on the host.
```

## 4. Quick 3-Step Deployment

### Step 1 — Copy the project to your Ubuntu server

```bash
# Option A: Git clone (if your repo is on GitHub/GitLab)
git clone https://github.com/your-org/Armss_photo_studio.git
cd Armss_photo_studio

# Option B: SCP from your Windows machine
# On Windows PowerShell:
scp -r "c:\Users\ARMSS GROUPS\Documents\Armss_photo_studio" ubuntu@<SERVER_IP>:/opt/armss-photo-studio
```

### Step 2 — Configure environment variables

```bash
cp .env.example .env
nano .env          # or: vim .env
```

**Minimum values to change before going live:**

```bash
# Your actual domain (e.g. studio.armss.in)
DOMAIN=studio.yourdomain.com

# Port exposed on the Ubuntu host (default 8070 — avoids collision with ARMSS-OTT on 8088)
GATEWAY_PORT=8070

# Full public URL (used in generated image links)
PUBLIC_BASE_URL=http://studio.yourdomain.com:8070

# Strong passwords
MYSQL_PASSWORD=YourStrongDBPassword2026
MINIO_ROOT_PASSWORD=YourStrongMinioPassword2026

# Auto-generated by deploy script, but you can set manually
SESSION_SECRET=<48-char random string>

# AI/Image generation (leave blank to disable gracefully — no crash)
ANTHROPIC_API_KEY=sk-ant-...
FLUX_API_KEY=...
```

### Step 3 — Run the automated deployment script

```bash
chmod +x deploy-ubuntu.sh
./deploy-ubuntu.sh
```

The script will:
1. ✅ Install Docker Engine & Docker Compose if missing
2. ✅ Auto-generate a secure `SESSION_SECRET` if `.env` doesn't exist
3. ✅ Stop any old containers (`docker compose down`)
4. ✅ Build all images with `--no-cache`
5. ✅ Start all 6 services in detached mode
6. ✅ Wait for the backend `/healthz` to turn healthy
7. ✅ Smoke-test the gateway endpoint
8. ✅ Print the live URL with maintenance cheatsheet

## 5. Port Allocation (Avoids Collision with ARMSS-OTT)

| Application | Default Host Port | Purpose |
|---|---|---|
| **ARMSS-OTT** | `8088` | OTT video platform gateway |
| **ARMSS Photo Studio** | `8070` | Photo studio gateway ← new |

All other ports (MySQL `3306`, MinIO `9000`/`9001`, Backend `8080`) are **internal only** — not exposed on the host, zero collision risk.

## 6. Configuring Your Reverse Proxy / Domain

On whichever server handles your public domain (Windows proxy, Nginx on another machine, Cloudflare Tunnel, etc.):

### If using Nginx (any OS):
```nginx
server {
    listen 80;
    server_name studio.yourdomain.com;

    client_max_body_size 100M;   # allow large image uploads

    location / {
        proxy_pass http://<UBUNTU_SERVER_IP>:8070;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;   # allow slow AI pipeline calls
    }
}
```

### If using Caddy:
```
studio.yourdomain.com {
    reverse_proxy <UBUNTU_SERVER_IP>:8070 {
        header_up Host {host}
        transport http {
            read_timeout 5m
        }
    }
}
```

### If using Windows IIS (ARR):
1. Open **IIS Manager** → Select your site for `studio.yourdomain.com`
2. Add **URL Rewrite Rule**:
   - Pattern: `(.*)`
   - Action Type: **Reverse Proxy**
   - Rewrite URL: `http://<UBUNTU_SERVER_IP>:8070/{R:1}`
3. Enable HTTP Request Routing → Enable proxy → Save

## 8. Running Both ARMSS-OTT and ARMSS Photo Studio on the Same Server

Both applications use **separate named Docker networks** and **separate named volumes** — they are fully isolated:

| Resource | ARMSS-OTT | ARMSS Photo Studio |
|---|---|---|
| Network | `armss_ott_network` | `armss_studio_network` |
| MySQL volume | `armss_ott_mysql_data` | `armss_studio_mysql_data` |
| Storage volume | `armss_ott_uploads_data` | `armss_studio_storage_data` |
| MinIO volume | `armss_ott_seaweedfs_data` | `armss_studio_minio_data` |
| Gateway port | `8088` | `8070` |

**Start both at the same time safely:**
```bash
# In the ARMSS-OTT directory
cd /opt/ARMSS-OTT && docker compose up -d

# In the Photo Studio directory (different terminal or after above)
cd /opt/armss-photo-studio && docker compose up -d
```

## 9. Storage Modes

The backend supports two storage drivers, set via `STORAGE_DRIVER` in `.env`:

| Mode | `STORAGE_DRIVER` | Description |
|---|---|---|
| **S3 (default)** | `s3` | Uses the MinIO container. Best for production. |
| **Local disk** | `local` | Files saved to `/app/data/storage` (Docker volume). Use for dev/testing without MinIO. |

To switch to local storage, update `.env`:
```bash
STORAGE_DRIVER=local
```
Then rebuild: `docker compose up -d --build backend`

## 10. Backup Procedures

### Backup MySQL database:
```bash
docker compose exec mysql mysqldump -uroot -p"${MYSQL_PASSWORD}" armss_poster_studio > backup_$(date +%Y%m%d).sql
```

### Backup MinIO data (all poster images):
```bash
# Copy the named volume contents
docker run --rm \
  -v armss_studio_minio_data:/source:ro \
  -v $(pwd)/backups:/backup \
  alpine tar czf /backup/minio_backup_$(date +%Y%m%d).tar.gz -C /source .
```

### Restore MySQL:
```bash
docker compose exec -T mysql mysql -uroot -p"${MYSQL_PASSWORD}" armss_poster_studio < backup_YYYYMMDD.sql
```

## 11. Troubleshooting

### Backend fails to start (`migration_failed`)
```bash
docker compose logs backend
# Usually means MySQL isn't ready yet — increase start_period in healthcheck or wait
docker compose restart backend
```

### Backend crashes with `required env var MYSQL_DSN is not set`
```bash
# Make sure .env exists and MYSQL_PASSWORD is set
cat .env | grep MYSQL_PASSWORD
```

### MinIO bucket not created
```bash
# Re-run the minio-init one-shot container
docker compose up minio-init
```

### Frontend shows blank page / API 404
```bash
# Check nginx is routing /api/ correctly
docker compose logs nginx
# Verify backend is healthy
docker compose ps
```

### Port 8070 already in use
```bash
sudo ss -tlnp | grep 8070
# Change GATEWAY_PORT in .env to a free port, then:
docker compose up -d nginx
```

## 12. First-Time Admin Setup

After deployment, seed the first admin user:

```bash
# Inside the backend container:
docker compose exec backend /app/armss-photo-studio seed \
    --email admin@armss.example \
    --password YourAdminPassword2026
```

> Or set `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` in `.env` and the container will auto-seed on first boot if a `cmd/seed` entrypoint is wired.

Then open `http://<SERVER_IP>:8070` in your browser and log in.
